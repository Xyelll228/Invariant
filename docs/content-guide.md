# Как устроена тема

Шаблон темы для авторов. Общие правила — в [ТЗ](tz.md): разделы «Структура контента», «Источники контента, лицензии и правила написания» и «Качество». Образец — черновик темы «Сортировка вставками» в `content/ru/algorithms/sorting/insertion-sort/`.

## Папка темы

Одна папка на тему: `content/ru/<раздел>/<модуль>/<тема>/`. Папка раздела и модуля берётся из `content/modules.yaml`: например, модуль `algo.sorting` лежит в `algorithms/sorting/`. Имя папки темы — любое понятное: `insertion-sort`.

| Файл | Что в нём | Обязателен |
| --- | --- | --- |
| `topic.yaml` | id, название, модуль, вид темы, уровни, предпосылки, термины, сложность, статус проверки | всегда |
| `fundament.mdx`, `base.mdx`, `depth.mdx` | тексты уровней из блоков `<Block>` | по одному на каждый уровень темы |
| `questions.yaml` | навыки, заблуждения, вопросы и задания генераторов | всегда |
| `sources.yaml` | источники, их лицензии и строка «Основано на» | всегда |
| `reference.ts` | эталонная реализация со следом | для алгоритмов |
| `mutants.ts` | испорченные версии, не меньше трёх | для алгоритмов |
| `vectors.json` | общие тестовые данные для JS, C++ и Python | для алгоритмов |
| `impl.cpp`, `impl.py` | версии на C++ и Python | для алгоритмов |
| `generators.ts` | генераторы заданий | если есть задания с генератором |

Термины лежат отдельно, по файлу на термин: `content/ru/glossary/<имя>.yaml`, id — `term.<имя>`.

## Идентификаторы

Идентификатор постоянный: не меняется при переименовании и никогда не используется повторно — на нём держится история повторений.

- Тема: `раздел.модуль.тема`, например `algo.sorting.insertion`. Id всех 427 тем каталога уже закреплены в `content/topics.yaml` — тема берёт id оттуда. Там же волна темы, если модуль выходит в нескольких волнах. Проверка сверяет названия в `content/topics.yaml` с `docs/catalog.md`.
- Адрес страницы строится из id, а не из имени папки: `algo.sorting.insertion` → `/ru/algorithms/sorting/insertion/`. Первый уровень темы — по адресу темы, остальные — в подпапке: `…/insertion/base/`. У блока — якорь с его id: `…/insertion/base/#algo.sorting.insertion.b.definition`.
- Внутри темы — с префиксом темы и буквой вида: блок `….b.имя`, вопрос `….q.имя`, навык `….s.имя`, заблуждение `….m.имя`.
- Только латинские буквы, цифры и дефисы; части через точку.

У блоков, вопросов, навыков и уровней есть номер версии. Исправление опечатки версию не меняет. Изменился смысл или ответ — версия растёт, и карточки повторения помечаются «изменено».

## topic.yaml

- `kind` — вид темы: `algorithm`, `structure`, `concept`, `language`, `sql`. От него зависят обязательные блоки.
- `levels` — уровни по порядку: `[fundament, base, depth]`; в разделе 0 — `[fundament, base]`; тема с пометкой (Г) в каталоге — только `[depth]`. Проверка сверяет уровни с каталогом.
- `prerequisites` — темы и уровни, которые нужны до этой. Граф предпосылок без циклов. Предпосылка выходит не позже темы: если она в более поздней волне, проверка остановит — перенос темы между волнами решает владелец.
- `confusableWith` — похожие темы. Если список не пуст, на каждом уровне нужен блок «Пары путаницы».
- `terms` — id терминов из глоссария.
- `complexity` и `code.cases` — для алгоритмов: заявленная сложность и какие данные дают лучший, средний и худший случай. Заявленную сложность проверяет эксперимент удвоения.
- `skipped` — необязательные блоки, которых нет, с причиной.
- `review.status`: `draft` — черновик, `auto` — проверено автоматически, `expert` — проверено экспертом.

## Блоки текста

Текст уровня состоит из блоков:

```mdx
<Block id="algo.sorting.insertion.b.idea" kind="explanation" version={1} title="Идея">

Текст блока.

</Block>
```

Виды блоков (`kind`) и где они обязательны:

| Блок | `kind` | Уровни | Для каких тем |
| --- | --- | --- | --- |
| Объяснение с примером | `explanation` | все | всех |
| Разобранный пример с подцелями | `worked-example` | Фундамент, База | всех |
| Визуализация и ручная симуляция | `visualization` | Фундамент, База | алгоритмов и структур данных |
| Код | `code` | База, Глубина | алгоритмов |
| Сложность и свойства | `complexity` | База | алгоритмов |
| Измерение на растущих данных | `measurement` | База, Глубина | алгоритмов |
| Доказательство | `proof` | База (идея), Глубина | алгоритмов |
| Частые ошибки и заблуждения | `misconceptions` | все | всех |
| Пары путаницы | `confusion-pairs` | все | если есть похожие темы |

Предвопросы, вопросы, термины, источники и статус проверки собираются из `questions.yaml`, `topic.yaml`, глоссария и `sources.yaml` — в тексте их не повторяем.

В текстах можно использовать только компоненты из `src/content/components.ts`. Всё, что можно вычислить, — состояния массива, ответы, числа операций — вычисляет эталон через компоненты, а не пишется руками.

| Компонент | Что показывает |
| --- | --- |
| `<Term id="term.…">текст</Term>` | Термин со ссылкой в глоссарий — при первом появлении. Термин должен быть в `terms` темы |
| `<TopicCode />` | Код темы во вкладках JavaScript, C++ и Python; код на JS запускается в песочнице. Только у алгоритма с полем `code`; можно задать примеры: `inputs={[[3, 1, 2]]}` |
| `<TraceSteps algorithm="…" input={[…]} />` | Разбор по шагам: этапы алгоритма, сравнения, обмены и массив после каждого этапа. Считается при сборке |
| `<ArrayTrace algorithm="…" input={[…]} />` | Визуализация массива: шаги, автопроигрывание, предсказание, свои данные, таблица шагов |
| `<ArraySimulation algorithm="…" input={[…]} />` | Ручная симуляция: человек сам выбирает обмены, каждый шаг сверяется со следом |

`algorithm` — id темы, эталон которой зарегистрирован в `src/lib/viz/algorithms.ts`. Для ручной работы данные маленькие: 5–8 элементов.

Доказательства (`kind="proof"`) на уровнях Фундамент и База свёрнуты, на Глубине — раскрыты. У каждого блока есть кнопка «Нашёл ошибку».

## questions.yaml

- `skills` — навыки. Карточка повторения — это навык, а не вопрос: при каждом повторении генератор даёт новый вариант.
- `misconceptions` — заблуждения: короткая формулировка, разбор и блок справочника, где это объясняется.
- `questions` — вопросы трёх видов: `choice` (выбор ответа), `free` (свободный ввод) и `generated` (задание генератора из `generators.ts`).
- У выбора ответа ровно один верный вариант (или `multiple: true`), а у каждого неверного — своё заблуждение.
- `role`: `pre` — предвопрос, `practice` — по ходу темы, `check` — итоговая и отложенная проверка.

Генератор получает генератор случайных чисел с зерном и возвращает условие и варианты. Ответ вычисляет эталон, неверные варианты — «неправильные алгоритмы», каждый со своим заблуждением. Если варианты совпали, данные генерируются заново.

## sources.yaml

- `basedOn` — строка на странице темы: «Основано на: …».
- `use: adapted` — текст опирается на источник. Лицензия: CC BY, CC BY-SA, CC0, общественное достояние, MIT или 0BSD.
- `use: reference` — сверка фактов, текст пересказываем своими словами. Дополнительно допустима PSF (документация Python).
- `use: read-more` — только ссылка в «читать дальше». Так даются закрытые книги.
- Лицензии с ограничениями NC и ND для `adapted` и `reference` запрещены.

## Правила написания, которые проверяет автоматика

- Предложение — не длиннее 30 слов.
- Нет слов «очевидно», «легко видеть», «тривиально» и восклицательных знаков.
- Нет запрещённых вариантов терминов из глоссария (поле `forbidden`), в любом падеже.
- Нет орфографических ошибок: слова проекта, которых нет в словарях, добавляются в `cspell-words.txt`.

## Проверки

| Команда | Что проверяет |
| --- | --- |
| `npm run check:content` | Схема, id, связи, обязательные блоки, вопросы, источники и лицензии, правила написания |
| `npm run check:code` | Эталон, версии на C++ и Python, свойства на случайных данных, мутанты, эксперимент удвоения, генераторы на 1000 вариантах |
| `npm run check:spelling` | Орфография в текстах тем, глоссарии и строках интерфейса |

Неполнота черновика — предупреждение. У темы со статусом `auto` или `expert` неполнота — ошибка: такая тема не публикуется.

Черновик на основном сайте не показывается. Его видно в превью правки и в сборке для автопроверок (`PUBLIC_SHOW_DRAFTS=1`) с пометкой «черновик».

## Тема готова, когда

Чек-лист из ТЗ, раздел «Качество»:

- Все три уровня написаны по шаблону; пропущенный блок имеет записанную причину.
- Термины есть в глоссарии, предпосылки указаны.
- На каждом уровне не меньше 10 вопросов или шаблонов минимум 4 типов, включая свободный ввод, и не меньше двух предвопросов.
- Для алгоритма: эталон со следом, не меньше 3 мутантов, визуализация, генераторы, версии на C++ и Python, эксперимент удвоения.
- Источники с лицензиями и строка «Основано на» на месте.
- Автопроверки зелёные, замечания обеих ИИ-рецензий закрыты, владелец прошёл тему на компьютере и телефоне.
