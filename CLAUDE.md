# «Инвариант» — памятка для Claude

Полное ТЗ — [docs/tz.md](docs/tz.md), каталог тем — [docs/catalog.md](docs/catalog.md). Это основная версия ТЗ. Если памятка и ТЗ расходятся, прав ТЗ, а расхождение исправляем через pull request.

## Проект

- Бесплатное открытое веб-приложение (PWA) для глубокого изучения алгоритмов и структур данных, баз данных и SQL, C и C++, Python, математики для информатики и подготовки к собеседованиям. Язык — русский; казахский и английский — в волне 6.
- 427 тем в 58 модулях, у каждой три уровня: Фундамент, База, Глубина. Каталог можно дополнять, но не сокращать.
- Статический сайт без своего сервера. Прогресс хранится только в браузере ученика (IndexedDB), есть экспорт и импорт в файл.
- Волны: 1 — ядро приложения и 59 тем; 2 — остальной раздел 1, часть математики, мини-проекты, «Контрольная», ИИ-наставник; 3 — базы данных и SQL; 4 — C, C++, Python и остальная математика; 5 — собеседования; 6 — переводы. Подробно — ТЗ, раздел «Этапы и критерии приёмки».

## Роли и решения

- Claude пишет код и контент. Проверяют автопроверки и две независимые ИИ-рецензии. Владелец проходит каждую правку на превью и принимает её. Эксперта-человека нет.
- Новая функция, раздел, тема или внешний сервис, которых нет в ТЗ, — только после явного «да» владельца. Сначала спросить: «Добавляем? Как лучше сделать?»
- Новая зависимость вне таблицы стека — с обоснованием и лицензией в описании PR.
- Владелец — автор проекта и его первый ученик: проходит каждую волну на себе. Решения объясняем простыми словами, действия в настройках GitHub даём пошаговой инструкцией.
- Не возвращаем отклонённое без запроса владельца: очки, серии, рейтинги, ежедневная цель и напоминания, «карта памяти», счётчик «к повторению» на главной, тест на пропуск уровня, PDF-шпаргалки, казахские термины до волны 6, форма ошибки без аккаунта GitHub, мини-проект «АВЛ-дерево».
- Настройки обучения по умолчанию меняются только с согласия владельца: порог «освоено» 80%, отложенная проверка не раньше чем через день, лимиты 10 новых и 100 повторений за учебный день, учебный день начинается в 4:00, верная догадка «наугад» — Again, после подсказки — не выше Hard, диагностика после перерыва дольше 30 дней.

## Стек

Astro (статическая сборка, MDX, коллекции контента со схемами Zod) · острова на Preact · TypeScript в строгом режиме · Dexie поверх IndexedDB · ts-fsrs (FSRS-6) · CodeMirror 6 · sql.js (SQLite не ниже 3.39), PGlite — с волны 3 · Pyodide — с волны 4 · KaTeX · MiniSearch (выбран на прототипе, [docs/search-prototype.md](docs/search-prototype.md)) · Workbox · Vitest, fast-check, Playwright, axe-core, Lighthouse CI.

Все зависимости — под свободными лицензиями, версии закреплены в lock-файле.

## Команды

Node.js 24 (файл `.nvmrc`).

- `npm run dev` — сайт для разработки. CSP в этом режиме Astro не включает.
- `npm run build` — сборка в `dist/` и Service Worker для работы без сети (`scripts/build-sw.mjs`, Workbox: оболочка приложения в кеше сразу, страницы тем — когда их открыли). Путь сайта задаёт `BASE_PATH`, по умолчанию `/Invariant/`. Черновики тем видны в превью правки и при `PUBLIC_SHOW_DRAFTS=1`, на основном сайте — нет.
- `npm run preview` — собранный сайт локально.
- `npm run check:types` — проверка типов.
- `npm test` — модульные тесты (Vitest).
- `npm run check:site` — ссылки, якоря и CSP в собранном сайте.
- `npm run check:licenses` — лицензии всех пакетов.
- `npm run check:content` — контент: схема, id, связи, обязательные блоки, вопросы, источники и лицензии, правила написания.
- `npm run check:code` — код тем: эталон, C++ (с санитайзерами) и Python, свойства, мутанты, эксперимент удвоения, генераторы. Нужны `g++` и `python3`.
- `npm run check:spelling` — орфография в текстах тем, глоссарии и строках интерфейса (словари `src/i18n`, компоненты и страницы); слова проекта — в `cspell-words.txt`.
- `npm run test:e2e` — сквозные тесты (Playwright). Свой Chromium локально: `PLAYWRIGHT_CHROMIUM_PATH=…`.
- `npm run lighthouse` — Lighthouse CI на профиле телефона.
- `npm run search:compare` — сравнение MiniSearch и Pagefind на 50 контрольных запросах; пишет отчёт `docs/search-prototype.md`. Не входит в CI.

Перед pull request прогоняем всё, что выше, кроме `dev`; сквозные тесты — хотя бы в Chromium. В CI они идут во всех трёх браузерах. Сквозные тесты, `check:site` и Lighthouse работают со сборкой с черновиками: `PUBLIC_SHOW_DRAFTS=1 npm run build` — так собирает CI.

## GitHub Pages

- Репозиторий `Xyelll228/Invariant`, проектный сайт `https://xyelll228.github.io/Invariant/`. В `astro.config`: `site: 'https://xyelll228.github.io'`, `base: '/Invariant'`. Внутренние ссылки и пути к файлам строятся от base, без абсолютных «/…».
- GitHub Actions собирает сайт и кладёт его в ветку `gh-pages`. Pages публикуется из ветки (Deploy from a branch), а не из Actions, иначе не работают превью.
- Превью каждой правки — `rossjrw/pr-preview-action@v1` в папку `/Invariant/pr-preview/pr-N/`; превью собирается со своим base и удаляется после закрытия PR. Для PR из форков превью не строятся. Нужны права Actions на запись (Settings → Actions → General → Workflow permissions).
- Основной деплой не стирает превью: у `JamesIves/github-pages-deploy-action` — `clean-exclude: pr-preview/` и `force: false`.
- Ограничения: сайт до 1 ГБ, мягкий лимит трафика 100 ГБ в месяц, публикация дольше 10 минут прерывается.
- Своих HTTP-заголовков нет: CSP задаётся тегом meta в каждой странице (`security.csp` в `astro.config.ts`). В meta не работают frame-ancestors, report-uri и sandbox.
- Встроенный скрипт — только с хешем через `Astro.csp?.insertScriptHash()` (пример — выбор темы в `BaseLayout.astro`). Атрибуты `style="…"` и `on…="…"` запрещены. Всё это проверяет `npm run check:site`.
- В `public/` лежит `.nojekyll`, а папка сборки называется `assets/` без подчёркивания: иначе Jekyll на GitHub Pages спрячет файлы.
- Все сайты Pages одного аккаунта — один источник `xyelll228.github.io` и видят хранилище друг друга. Поэтому: других сайтов на Pages на аккаунте владельца нет; база IndexedDB называется `invariant`, у превью — своя база с номером PR, а прототип хранилища пишет в отдельную базу с суффиксом `-prototype`; Service Worker основного сайта не обслуживает `/Invariant/pr-preview/`; ключ API по умолчанию живёт только в памяти вкладки.

## Безопасность и приватность — не нарушать

- Код ученика выполняется только в iframe с `sandbox="allow-scripts"` **без** `allow-same-origin` — эти два флага никогда не ставятся вместе. Внутри — Web Worker с лимитом времени (по умолчанию 2 секунды на тест), который по таймауту уничтожается и создаётся заново. CSP песочницы запрещает сеть.
- Страница песочницы `sandbox/runner.html` выполняет код, только если её источник непрозрачный (`self.origin === 'null'`) и она вложена в другое окно. Эту проверку не убираем: без неё чужой сайт встроит страницу без sandbox и запустит код с источником приложения, то есть с доступом к его хранилищу.
- Скрипты, шрифты, Pyodide и PGlite лежат на нашем сайте. Сторонних скриптов, CDN, рекламы и аналитики нет.
- Сетевые запросы — только к своему сайту и к API наставника, и только по действию ученика.
- Ключ API — только в браузере ученика: по умолчанию в памяти вкладки, «запомнить на этом устройстве» — по его выбору. Ключ не попадает в экспорт, логи и репозиторий. В запросах к API нет данных о человеке — только текст темы, вопрос и код.
- Персональные данные не собираем. Данные в примерах и учебных базах придуманы.
- Секретов в репозитории нет.

## Контент

- Формат темы — [docs/content-guide.md](docs/content-guide.md); образец — черновик `content/ru/algorithms/sorting/insertion-sort/`.
- Одна папка на тему: `content/ru/<раздел>/<модуль>/<тема>/` — `topic.yaml`, `fundament.mdx`, `base.mdx`, `depth.mdx`, `questions.yaml`, `sources.yaml`, для алгоритмов ещё `reference.ts`, `mutants.ts`, `vectors.json`, `impl.cpp`, `impl.py`, `generators.ts`. Термины — `content/ru/glossary/`, id модулей — `content/modules.yaml`, id и волны всех 427 тем — `content/topics.yaml`.
- Адрес страницы строится из id темы, а не из папки: `algo.sorting.insertion` → `/ru/algorithms/sorting/insertion/`, уровни База и Глубина — `…/base/`, `…/depth/`, у блока — якорь с его id.
- Черновик (`review.status: draft`) не публикуется как тема; его неполнота — предупреждение проверки. У опубликованной темы неполнота — ошибка.
- Id тем, блоков, вопросов и навыков постоянные и повторно не используются; у каждого есть версия. Исправление опечатки историю повторений не трогает. Если изменился смысл или ответ — новая версия, карточка помечается «изменено».
- Всё, что можно вычислить, вычисляет эталонный код: ответы, следы, счётчики операций, эксперимент удвоения. Руками не пишем.
- Правила написания (ТЗ, раздел «Источники контента, лицензии и правила написания»): короткие предложения; термины только из глоссария; у каждого проверяемого утверждения — источник; в тексте только код, запущенный при сборке; сложность всегда с условием («в среднем», «в худшем случае», «амортизированно»); никаких «очевидно»; рисунки свои, в SVG; строка «Основано на: …».
- Лицензии: код — MIT, контент — CC BY-SA 4.0. Источники только с совместимыми лицензиями; NC и ND запрещены. Закрытые книги — только в «читать дальше», своими словами. На LeetCode и подобные площадки — только ссылки.
- Тон интерфейса нейтральный: без «молодец!» и восклицательных знаков.
- Факты о внешнем мире — версии, лимиты, лицензии, поведение СУБД и браузеров — сверяем с первоисточником, прежде чем писать.

## Проверка контента

Конвейер: черновик → автопроверки → две ИИ-рецензии → владелец на превью (компьютер и телефон) → публикация со статусом «проверено автоматически» → сообщения учеников.

- Каждая рецензия — отдельный запуск (субагент) с чистым контекстом; рецензент не видит рассуждений автора.
  1. Сверка с источником: для каждого проверяемого утверждения — подтверждающая цитата из открытого источника, указанного в теме. Нет цитаты — утверждение исправляется или получает другой источник.
  2. Оппонент: контрпримеры, пропущенные граничные случаи, дыры в доказательствах, неоднозначные вопросы, противоречия между уровнями, ошибки в терминах.
- Замечания рецензий — комментариями к PR; все закрываются до слияния.
- Тема готова по чек-листу «Тема готова» (ТЗ, раздел «Качество: проверка контента и тесты»).
- Подтверждённая ошибка после публикации: исправление не дольше 7 дней, новая автопроверка, которая поймала бы такую ошибку, и запись в журнале изменений.

## Как работаем

- В `main` напрямую не пишем: ветка → PR → зелёные проверки → ссылка на превью → проверка владельцем → слияние после его «принято».
- Описания PR, коммиты и отчёты владельцу — по-русски и простыми словами: что сделано, как проверить на превью, что осталось.
- Правки ТЗ и каталога — тоже через PR и только с согласия владельца.
