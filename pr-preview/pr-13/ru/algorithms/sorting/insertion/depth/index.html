Обмены и инверсии

Инверсия — пара индексов i < j, для которой a[i] > a[j]: два элемента стоят в неправильном порядке. В упорядоченном массиве инверсий нет. В массиве из n различных элементов, упорядоченном по убыванию, инверсия — каждая пара, всего их n(n − 1)/2.

Сортировка вставками меняет местами только соседей, у которых a[j − 1] > a[j]. Такой обмен исправляет порядок этой пары. Любой другой элемент стоит левее обоих соседей или правее обоих — и до обмена, и после. Поэтому его пары с ними не меняются, и обмен уменьшает число инверсий ровно на один.

В конце инверсий нет. Значит, обменов ровно столько, сколько инверсий в исходном массиве. Обозначим это число I.

Отсюда видно, почему сортировка адаптивна: работа растёт вместе с беспорядком в данных, а не только с длиной. Например, если каждый элемент стоит не дальше чем в k ≥ 1 позициях от своего места, сортировка работает за O(nk).

Точный подсчёт сравнений

Сравнением считаем проверку a[j − 1] > a[j]. Вставка элемента заканчивается одним из двух способов.

  • Сравнение оказалось ложным. Тогда сравнений при этой вставке на одно больше, чем обменов.
  • Элемент дошёл до начала, j = 0. Неудачного сравнения не было, и сравнений столько же, сколько обменов.

Пусть z — число элементов, которые при вставке дошли до начала массива. Это элементы с индексом i ≥ 1, строго меньшие всех элементов левее них. Тогда для массива из n ≥ 1 элементов число сравнений

C=I+(n−1)−z.C = I + (n - 1) - z.

Число z — от 0 до n − 1, поэтому сравнений не меньше I и не больше I + n − 1.

  • Упорядоченный массив и массив из равных элементов: I = 0, z = 0, сравнений n − 1.
  • Различные элементы по убыванию: I = n(n − 1)/2, z = n − 1, сравнений n(n − 1)/2.
  • Случайная перестановка различных чисел: в среднем I = n(n − 1)/4, а сравнений на O(n) больше.

Эти формулы при каждой сборке проверяет код темы: на тестовых данных, на случайных массивах и на всех перестановках малой длины.

Инвариант и доказательство корректности

Докажем, что функция возвращает упорядоченную перестановку исходного массива. Доказательство опирается на два инварианта цикла.

Внешний цикл. Перед каждой проверкой условия i < n в ячейках a[0..i − 1] лежат те же элементы, что были там вначале, только упорядоченные. Ячейки a[i..n − 1] ещё не тронуты.

При i = 1 часть a[0..0] из одного элемента упорядочена.

Внутренний цикл. Пусть вставляется элемент x, который вначале стоял в a[i]. Перед каждой проверкой условия внутреннего цикла:

  1. x стоит в ячейке a[j];
  2. части a[0..j − 1] и a[j + 1..i] упорядочены;
  3. каждый элемент из a[j + 1..i] строго больше x;
  4. если обе части не пусты, a[j − 1] ≤ a[j + 1].

Вначале j = i. Часть a[j + 1..i] пуста, а a[0..i − 1] упорядочена по инварианту внешнего цикла. Обмен выполняется, только если a[j − 1] > x. После обмена и j ← j − 1 бывший элемент a[j − 1] стоит первым в правой части. Он больше x и, по свойству 4, не больше остальных элементов правой части. Свойство 4 для нового j верно, потому что левая часть упорядочена. Остальные свойства тоже сохраняются.

Выход из внутреннего цикла. Цикл заканчивается, когда j = 0 или a[j − 1] ≤ x. В обоих случаях левее x стоят элементы не больше него, а правее — большие. Значит, часть a[0..i] упорядочена. Элементы переставлялись только внутри неё, поэтому инвариант внешнего цикла верен для i + 1.

Завершение. Каждый обмен уменьшает j, а цикл останавливается не позже j = 0. Внешний цикл увеличивает i до n. При i = n по инварианту весь массив a[0..n − 1] упорядочен и состоит из исходных элементов.

Варианты: сдвиги и бинарные вставки

Вставка сдвигами. Обмен соседей записывает в массив две ячейки. Можно иначе: запомнить вставляемый элемент в переменной key и сдвигать большие элементы вправо по одному, a[j] = a[j − 1]. В конце key записывается в освободившуюся ячейку. Сравнения те же, а записей I + (n − 1) вместо 2I: когда инверсий много, почти вдвое меньше.

Код можно изменить и запустить: он выполняется в песочнице прямо в браузере.

function insertionSortShift(a) {
  for (let i = 1; i < a.length; i++) {
    const key = a[i];
    let j = i;
    while (j > 0 && a[j - 1] > key) {
      a[j] = a[j - 1];
      j--;
    }
    a[j] = key;
  }
  return a;
}

def insertion_sort_shift(a: list[int]) -> list[int]:
    """Вставка сдвигами: тот же алгоритм, что insertionSortShift на JavaScript."""
    for i in range(1, len(a)):
        key = a[i]
        j = i
        while j > 0 and a[j - 1] > key:
            a[j] = a[j - 1]
            j -= 1
        a[j] = key
    return a

Бинарные вставки. Левая часть упорядочена, поэтому место для key можно найти бинарным поиском. При вставке элемента с индексом i это не больше ⌈log₂(i + 1)⌉ сравнений, а поиск подряд делает до i. Всего сравнений O(n log n).

Сдвиги остаются прежними: элементы, которые больше key, всё равно сдвигаются по одному. Поэтому в среднем и худшем случае время по-прежнему Θ(n²).

Чтобы сортировка осталась устойчивой, поиск ищет первое место, где элемент строго больше key. Тогда элементы, равные key, остаются левее, и порядок равных сохраняется.

Код можно изменить и запустить: он выполняется в песочнице прямо в браузере.

function binaryInsertionSort(a) {
  for (let i = 1; i < a.length; i++) {
    const key = a[i];
    // Первое место в a[0..i - 1], где элемент больше key: равные остаются левее.
    let lo = 0;
    let hi = i;
    while (lo < hi) {
      const mid = lo + Math.floor((hi - lo) / 2);
      if (a[mid] > key) hi = mid;
      else lo = mid + 1;
    }
    for (let j = i; j > lo; j--) a[j] = a[j - 1];
    a[lo] = key;
  }
  return a;
}

Где применяют

На больших массивах сортировки слиянием и быстрая намного эффективнее вставок, но у них больше накладные расходы. На коротких массивах простая сортировка вставками выигрывает. Поэтому библиотечные сортировки досортировывают ею маленькие куски.

  • Сортировка в libstdc++, стандартной библиотеке C++ компилятора GCC, — это introsort. Отрезки короче 16 элементов она досортировывает вставками.
  • Сортировка в Go для отрезков из 12 элементов и меньше тоже использует вставки.
  • Сортировка списков в Python (list.sort в CPython) ищет в данных уже упорядоченные куски. Короткий кусок она дополняет до нужной длины бинарными вставками. Массив короче 64 элементов она сортирует бинарными вставками целиком.

Ещё сортировка вставками — онлайн-алгоритм: она может получать элементы по одному и держать уже полученные упорядоченными.

Ваша заметка

Частые ошибки

  • «Бинарный поиск делает сортировку вставками O(n log n)». Он сокращает сравнения, но не сдвиги: в среднем и худшем случае их по-прежнему Θ(n²).
  • «Число обменов зависит только от длины массива». Оно равно числу инверсий: от 0 на упорядоченном массиве до n(n − 1)/2 на массиве различных элементов по убыванию.
  • «Бинарные вставки всегда делают меньше сравнений». На упорядоченном массиве обычной вставке хватает n − 1 сравнений, а бинарный поиск делает около log₂ i сравнений на каждый элемент.
  • «В бинарных вставках не важно, искать место, где элемент больше key или не меньше key». Массив упорядочится в обоих случаях, но во втором равные элементы меняются местами, и сортировка теряет устойчивость.

Ваша заметка

Вставки или выбор: что считать

  • Работа вставок зависит от числа инверсий I: обменов ровно I, сравнений от I до I + n − 1.
  • Сортировка выбором на любом массиве из n элементов делает одно и то же число сравнений. На каждом шаге она просматривает всю правую часть: если в ней m элементов, это m − 1 сравнений. Всего (n − 1) + (n − 2) + … + 1 = n(n − 1)/2. Обменов у неё не больше одного за шаг — не больше n − 1.

Поэтому на почти упорядоченных данных вставки делают намного меньше сравнений, а на случайных выбор намного реже пишет в массив.

Термины

массив (array)
Последовательность элементов, у каждого из которых есть номер — индекс. Элемент можно прочитать или заменить по его индексу.
индекс (index)
Номер элемента в массиве. В «Инварианте» индексы считаются с нуля: у первого элемента индекс 0, у последнего в массиве длины n — индекс n − 1.
устойчивая сортировка (stable sort)
Сортировка, которая сохраняет взаимный порядок элементов с равными ключами: если элемент x стоял раньше элемента y и ключи у них равны, после сортировки x по-прежнему стоит раньше y.
сортировка на месте (in-place sort)
Сортировка, при которой элементы переставляются внутри самого массива, а вне его одновременно хранится лишь постоянное число элементов.
инвариант цикла (loop invariant)
Утверждение, которое верно каждый раз перед проверкой условия цикла: до первой итерации, после каждой итерации и поэтому при выходе из цикла. Через инвариант доказывают, что цикл делает то, что нужно.
лучший случай (best case)
Входные данные размера n, на которых алгоритм делает меньше всего операций, и само это наименьшее число операций.
худший случай (worst case)
Входные данные размера n, на которых алгоритм делает больше всего операций, и само это наибольшее число операций.
средний случай (average case)
Среднее число операций по всем входным данным размера n. Обычно считают, что все перестановки входа равновероятны; другое распределение называют явно.
O-большое (big O)
Запись f(n) = O(g(n)) значит: есть постоянная c > 0, что f(n) ≤ c · g(n) при всех достаточно больших n. Это оценка сверху с точностью до постоянного множителя.
Θ-большое (big Theta)
Запись f(n) = Θ(g(n)) значит: есть постоянные c₁, c₂ > 0, что c₁ · g(n) ≤ f(n) ≤ c₂ · g(n) при всех достаточно больших n. Это точная оценка роста — и сверху, и снизу.
адаптивная сортировка (adaptive sort)
Сортировка, которая работает быстрее на почти упорядоченных данных: число её операций зависит от того, насколько беспорядочен вход, а не только от его длины.
инверсия (inversion)
Пара индексов i < j, для которой a[i] > a[j]: два элемента стоят в неправильном относительном порядке. В упорядоченном по возрастанию массиве инверсий нет.
онлайн-алгоритм (online algorithm)
Алгоритм, который обрабатывает данные по мере поступления и не ждёт, пока придёт весь вход.
бинарный поиск (binary search)
Поиск в упорядоченном массиве: на каждом шаге искомое значение сравнивается с элементом в середине отрезка, и половина отрезка, где искомого быть не может, отбрасывается.
